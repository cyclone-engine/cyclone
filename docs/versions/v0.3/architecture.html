Cyclone — cấu trúc các tầng & cách nó chạy

Cyclone là một deterministic tick-simulation engine viết bằng Rust (1 crate duy nhất, /root/.cline/index/cyclone), tách bạch simulation, snapshot, giao thức mạng và I/O thật thành 9 module phụ thuộc một chiều. Bên dưới là sơ đồ tầng, luồng thực thi theo đúng lời gọi hàm trong mã nguồn, và chi tiết từng module.

02Luồng thực thi — theo đúng thứ tự gọi hàm

Đây là chuỗi sự kiện thật khi Cyclone chạy: từ lúc process khởi động, qua vòng lặp tick, tới lúc snapshot được nén thành delta và bắn qua TCP tới client — rồi chiều ngược lại khi client nhận. Tên hàm/struct dưới đây lấy trực tiếp từ mã nguồn.

Khởi động

Tạo World & spawn entity ban đầu

World::new() rồi gọi world.spawn(obj) cho từng entity khởi đầu. Bên trong, spawn() đẩy PendingCommand::Spawn vào hàng đợi rồi flush(TickId(0)) áp dụng ngay lập tức.

Khởi động (nếu có networking)

Mở cổng lắng nghe

Server::bind(addr) mở TcpListener; vòng lặp server gọi server.accept() (chặn) tới khi có client, trả về Connection::new(stream).

Vòng lặp chính

Runner đo thời gian thật và sinh tick

Runner::run() lặp while should_continue(): đo elapsed từ Instant::now(), gọi TickScheduler::advance(elapsed) — hàm này tích luỹ elapsed vào accumulator và trả về Vec<TickId> (0, 1, hoặc nhiều tick nếu frame bị trễ — catch-up).

Vòng lặp chính

World chạy tick — gọi vào gameplay

Với mỗi TickId, World::tick() duyệt mọi entity còn alive && enabled, gọi object.on_tick(&TickInfo, &mut Commands) — đây là nơi code gameplay của người dùng chạy. Cuối tick, flush() áp dụng toàn bộ spawn/despawn đã hàng đợi (gọi on_spawn/on_despawn, cascade xuống children).

Sau mỗi tick / định kỳ

Chụp snapshot toàn world

World::snapshot(tick) duyệt entity còn sống, gọi object.write_snapshot(&mut SnapshotWriter) để gameplay tự nguyện phơi field, đóng gói thành SnapshotItem, rồi snapshot.sort() theo EntityId (bất biến bắt buộc cho bước diff kế tiếp).

Replication

So sánh với baseline của từng client

Mỗi client giữ 1 SnapshotSender. next_message(&latest): lần đầu trả Outgoing::Snapshot (full), các lần sau gọi snapshot::diff(baseline, latest) — merge tuyến tính O(n) trên 2 mảng đã sort — trả Outgoing::Delta chỉ chứa phần đổi.

Replication → mạng

Encode và gửi qua socket

send_outgoing() convert Snapshot/SnapshotDelta sang WireSnapshot/WireDelta, đóng gói thành Packet (header 9 byte: magic + version + kind + độ dài payload), rồi Connection::send() gọi stream.write_all() — điểm chạm socket duy nhất khi ghi.

Phía nhận

Ghép byte phân mảnh & decode

Connection::recv() gọi PacketReader::try_read_packet(); nếu buffer chưa đủ header/payload thì đọc thêm từ stream.read() và feed() tiếp — xử lý đúng việc TCP có thể chia nhỏ 1 packet thành nhiều lần đọc.

Phía nhận

Tái tạo state từ delta

Decode WireSnapshot/WireDelta về type nội bộ, rồi nếu là delta thì gọi replication::apply(old, delta, tick) — merge tuyến tính đối xứng với diff() — để dựng lại Snapshot mới nhất, cập nhật baseline cho lần nhận kế tiếp.

runtime

Tách bạch rõ: TickScheduler là toán học thuần (fixed-timestep, accumulator), Runner là nơi duy nhất chạm Instant thật. Lưu ý: Runner hiện chỉ drive World — chưa tự gọi snapshot/replication/net.

pub fn advance(&mut self, elapsed: Duration) -> Vec<TickId>

pub fn run(&mut self, world: &mut World, mut should_continue: impl FnMut() -> bool) {
    while should_continue() {
        let elapsed = Instant::now() - last;
        for tick in self.scheduler.advance(elapsed) {
            world.tick(tick);
        }
    }
}

pub struct SnapshotSender { baseline: Option<Snapshot> }
impl SnapshotSender {
    pub fn next_message(&mut self, latest: &Snapshot) -> Outgoing {
        match &self.baseline {
            None => Outgoing::Snapshot(latest.clone()),
            Some(b) => Outgoing::Delta(diff(Some(b), latest)),
        }
    }
}

04Nguyên tắc ranh giới đang chi phối kiến trúc

Đây là các quy tắc thiết kế cứng của dự án — mọi module engine phải giữ được ngay cả khi xoá hết code gameplay.

→

Gameplay → Engine, không bao giờ ngược lại. Engine không được biết khái niệm gameplay cụ thể (Tee, Hook, Weapon…). Xoá toàn bộ code gameplay thì engine vẫn phải compile được.

→

World → Snapshot → Protocol → Transport, một chiều. Snapshot không biết UDP/Packet/Ack; Protocol chỉ là adapter Snapshot ↔ Packet, có thể có nhiều implementation song song mà engine không cần biết đang dùng cái nào.

→

Object không bao giờ biết World, Snapshot hay mạng. Nó chỉ thấy TickInfo, Commands, SnapshotWriter — ranh giới này giữ gameplay độc lập hoàn toàn khỏi replication/networking.

→

Mỗi cặp tầng tách logic thuần khỏi I/O thật: TickScheduler (thuần) vs Runner (chạm Instant); PacketReader (thuần) vs Connection (chạm TcpStream).

→

1 crate, chỉ tách module — chưa tách nhiều crate, chưa ECS đầy đủ. Ưu tiên kiến trúc rõ ràng, đơn giản; tối ưu hoá backend lưu trữ sẽ quyết định sau khi có benchmark thật, không dựa trên giả định.
